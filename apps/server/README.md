# ARAGOZ single-process server

Use Node 24. Root start: `node --env-file-if-exists=.env apps/server/src/index.ts`.
`createApp(configOverrides?, dependencies?)` is exported by `src/app.ts` for injection without listening. Dependencies accept `now`, `fetch`, `socketFactory`, `store`, and `background:false`. There are no development authentication routes. Tests establish an internal database fixture, then use the same cookie, authorization and CSRF middleware as production.

Configuration: `PUBLIC_ORIGIN`, `PORT`, `HOST` (default loopback), `DATABASE_PATH`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `TWITCH_REDIRECT_URI`, `CREDENTIAL_ENCRYPTION_KEY` (base64 encoding of exactly 32 random bytes), `INVITED_BROADCASTER_IDS` (comma separated login names or account IDs), `OPENAI_API_KEY`, `MODEL_DAILY_REQUEST_LIMIT` (default **0**, disabling model requests), `MAX_ACTIVE_SHOWS` (default **3**, clamped to 0-3 for the whole deployment), `WEB_DIST_PATH`. Never put these values in client code. The single persistent SQLite database needs a writable durable volume. Explicitly bind an appropriate deployment host when deploying behind a reverse proxy; the service does not trust forwarded IP headers by default.

Get `/api/session` first. It sets an HttpOnly SameSite=Lax cookie and returns the CSRF token. Include credentials and `X-CSRF-Token` on every POST/DELETE. Host resources, backstage, recipes, showbill and WebSocket transport require an invited authenticated broadcaster; there are no public display links. WebSockets additionally require an exact configured Origin. All actions and event uploads include the current `expectedRevision`. A 409 means fetch the latest snapshot. Exact already-committed event batches are acknowledged despite their old revision; they never create another result or advance a replacement/ended attempt. Session information's `hostingConfigured` reports deployment configuration, and `authenticated` reports a verified OAuth host session.

Host setup uses owner-authenticated `GET /api/connection` and CSRF-protected `POST /api/connection/test`. Both return `{connected, chatHelpGranted, testCode, lastTestAt}`. POST creates a fresh six-hex challenge for ten minutes and clears prior verification. A genuine incoming `!aragoz CODE` for the same channel confirms it once; wrong/expired codes and duplicate EventSub deliveries cannot confirm a test. No message is sent and no write permission is needed. Verification is held in memory and is reset by server restart, OAuth reconnect or explicit disconnect. The response never includes chat text or viewer identity.

`!make ABC123 power BUT flaw` and `!vote ABC123 A` use the room's six-character roundCode. Tokens rotate per ballot/restart, with a distinct second-slot ballot. Proposals open after the configured broadcast delay for 25 seconds; votes open after that delay for 20 seconds. Messages must arrive during the current window and have Twitch timestamps inside it. Out-of-order updates compare timestamps then Twitch message IDs; EventSub delivery IDs are deduplicated in SQLite. Shared Chat relays are ignored. A deterministic salted contributor reservoir caps eligible proposals at 128; a compilation uses at most 12 unique authors, with recent featured authors behind others. Only explicit commands are stored; ordinary chat is not logged. `!help` writes only after OAuth write opt-in plus per-show setting, at most once per 30 seconds.

`use-house` replaces an authoring ballot with three genuinely credited House Suggestions in review. `close-vote` can choose a House fallback immediately from that review. Audience candidates require `approve-candidates` before `open-vote`. All three profiles must be distinct and the second slot excludes the first slot's family. The first House ballot spans charge, steam and echo. No votes selects a credited House rule. Supported model mappings must pass application semantic validation; adaptations show the exact replacement power/flaw from the shipped catalogue and still need host approval. Arbitrary model-authored explanation text is never published. The model sees only proposal IDs/raw strings and the fixed mechanic catalog. Requests use strict Responses structured output with gpt-6-luna, moderation, a shared 12-second deadline and at most one repair. Every moderation/compile HTTP request counts against the SQLite daily limit.

When the model is disabled, its allowance is exhausted or a provider request fails, a strict English catalogue grammar can preserve genuine audience authorship without a model request. Clear examples are `charges at you BUT cannot turn once it starts`, `steam BUT overheats`, and `copies your last second of movement BUT blocks expose its mirror`. Only recognized power-and-flaw pairs map to fixed profiles; unknown wording, extra instructions, unsupported flaws and arbitrary text receive no audience mapping. Remaining choices are labelled House Suggestions. Catalogue matches preserve the real proposal/author, have no adaptation, require host approval and set a visible `Catalogue fallback` room notice. A provider-flagged proposal cannot reappear through this fallback. This narrow grammar is not a general substitute for provider moderation or human review.

An assembled recipe is persisted before combat. Claim control with a stable browser `clientId` before `start-combat`. A different client needs `takeover:true`; a running encounter also requires explicit takeover when the same client reloads. Explicit takeover of running or paused combat records abandonment of the old attempt and creates a fresh paused attempt with an empty sequence ledger; ordinary controlling-tab pause/resume keeps its existing attempt. Resume the fresh attempt after the stage appears. Opening backstage/WebSocket never creates an attempt. Events use monotonically increasing sequences within the active attempt and the committed hash. This is a host-led local simulation ledger, not competitive anti-cheat. On input loss the committed fight can continue locally; unfinished audience ballots are invalidated with no gap replay. Restart invalidates unfinished authoring and abandons running combat, creating a paused fresh attempt. Deadlines are suspended during ordinary host pause/resume.

Remix replaces one slot and commits a new recipe; Encore/Retry keeps the original recipe and creates a new attempt. Three acts lead to showbill. The deployment admits at most `MAX_ACTIVE_SHOWS` active shows across all channels, with a hard ceiling of three and one active show per channel. Ended shows and final showbills do not occupy an active slot; Encore, Retry and Remix reactivation must acquire that slot again. Completed saved shows have no arbitrary per-channel count cap. Each room has an independent queue: a compiler awaiting its bounded response cannot suspend another room's deadline transitions. Later author hiding is a presentation setting: render a credit hidden when `room.settings.hideAuthors || credit.hidden`. Immutable stored recipe hashes remain stable, so consumers must honor the room setting when showing recipe/showbill credits.

Schema migrations use `PRAGMA user_version`; startup rejects an unknown newer database. All raw proposals expire after24hours, with hourly pruning and startup pruning. Accepted immutable contracts retain source proposal IDs, author attribution and the normalized rule, without the original chat text. Deleting a show cascades proposals, votes, recipes, results and encounter events. Host/moderation rejections update the stored message independently of timestamp ordering for later chat edits. OAuth state is single-use and expires after ten minutes; a newer authorization start invalidates earlier states and in-flight callbacks for that session. Disconnect/reconnect generations invalidate pending token refresh and EventSub welcome callbacks, so old responses cannot restore a removed credential or socket. Access/refresh tokens use AES-256-GCM; refresh is serialized per channel, and token validation runs at startup and at least hourly. A definitive token rejection or authorization revocation removes the stored credential and host sessions; a transient periodic validation failure closes the old socket and retries. EventSub handles welcome subscription creation, keepalive timeout, handoff reconnect without resubscription, ordinary reconnect with resubscription, revocation and platform-managed protocol Ping/Pong. Failure of a pending handoff preserves a still-healthy original connection.

Internal backup: `node --env-file-if-exists=.env apps/server/src/backup.ts /absolute/new-backup.sqlite`. The destination must not exist. The API has no backup/download endpoint. To restore, stop this single process, preserve its database and sidecars, then restore a verified backup to the configured database path with matching encryption key before restarting. The tests reopen a backup and compare the persisted recipe/channel identity. Production startup also serves `apps/web/dist` if present.
